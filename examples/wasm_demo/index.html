About Moduletto Native Smart


                    

                        
FIPS 203 conformant. The ML-KEM-512 implementation is
                        validated against the official NIST ACVP known-answer vectors — 25 keyGen,
                        25 encapsulation and 10 decapsulation cases (including modified-ciphertext
                        rejection), run against all three backends on every build. Self-consistency
                        checks cannot establish this: an implementation can encapsulate and decapsulate
                        in perfect agreement with itself and still not be ML-KEM.

                    


                    
What makes it fast:

                    
    
                        
  • Lazy reduction — with q = 3329 in a 64-bit register
                            there are ~50 spare bits, so the NTT keeps coefficients in a redundant
                            centred form through all seven layers and canonicalises once at the end.
                            Only multiplies are reduced, by a branchless rounding Barrett step.
    • 
                        
  • Constant-time at no cost — the kernel is straight-line
                            arithmetic with no data-dependent branch and no conditional move, so the
                            ct_* transforms are the same code as the variable-time ones and
                            run at the same speed. Nothing for an optimisation barrier to protect.
    • 
                        
  • Vectorised NTT on ARM64 — native builds narrow to
                            int16 and run eight Montgomery butterflies per NEON instruction, all seven
                            layers included. This page does not use that path; see below.
    • 
                        
  • Two-lane Keccak — native builds drive two independent
                            SHAKE sponges through the ARMv8.2 SHA3 instructions at once, since those
                            operate on 128-bit vectors holding two Keccak lanes.
    • 
                        
  • Machine-checked proofs — the Barrett reductions,
                            constant-time primitives and NTT correctness carry Coq developments in
                            proofs/.
    • 
                    


                    

                        
What you are actually running here. This page is compiled to
                        wasm32-unknown-unknown, which has no NEON, so it exercises the
                        portable i64 kernel — the same code path a non-ARM64 native build
                        takes. Expect it to be several times slower than the figures quoted for Apple
                        Silicon, and slower again for running inside a JavaScript engine. That the
                        results still match the native ones bit for bit is the useful part: it is an
                        independent cross-target check of the same arithmetic.

Features:

                    
    
                        
  • Constant-time operations — side-channel resistant,
                            with subtle optimisation barriers on the scalar primitives
    • 
                        
  • Type-safe modulus — the modulus lives in the type, so
                            mixing two of them is a compile error
    • 
                        
  • Zero heap allocations — stack memory only
    • 
                        
  • no_std compatible — twiddle tables are built by const
                            evaluation rather than lazily at runtime, so the NTT needs no allocator and
                            no std
    •
